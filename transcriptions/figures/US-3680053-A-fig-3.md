## Patent prose — PRIMARY EVIDENCE, separately attributed

The introductory description defines a fifteen-wire parallel highway: ten data wires, four code wires and one strobe wire. A character has ten data bits transferred simultaneously. The Figure 3 description calls DD the data-drive unit and CD the code/control-drive unit associated with a highway-drive control unit.

It explicitly says the incoming data are supplied both to DATA SENSE and to ten two-input AND gates GDB1–GDB10, only first/last being expanded. IDT means “inhibit data through”. IA inverts IDT, so asserting IDT to one closes the through gates. IB inverts that result; the resulting one primes local-launch gates GSC1–GSC10. Their outputs combine with the through paths at OR gates GDS1–GDS10.

The code description identifies ICT as “inhibit code through”, with CODE SENSE and CODE LAUNCH routes. The strobe description identifies IST as “inhibit strobe through”, with corresponding STROBE SENSE and STROBE LAUNCH.

The prose's general logic convention identifies circles containing 1 as OR gates and circles containing a larger numeral as AND gates; the Figure 3 discussion explicitly calls the data-through gates two-input AND gates and their output combiners OR gates. IA–ID are inverters.

Using those prose-supplied logic functions, the depicted channel relations are:

```text
data_out[i]   = (data_in[i] AND NOT IDT)
                OR (data_launch[i] AND IDT)

code_out[j]   = (code_in[j] AND NOT ICT)
                OR code_launch[j]

strobe_out    = (strobe_in AND NOT IST)
                OR strobe_launch
```

These are a functional restatement of the visible connections and the prose's gate definitions, not printed equations in Figure 3. The distinction between gated data launch and direct code/strobe launch is retained.

The surrounding prose describes breaking selected parts of the ring to insert local data, control codes and strobes, with arbitration/selection procedures explained in other figures. None of those state machines or code decoders is drawn inside Figure 3.

## Uncertainties, discrepancies and limits

- **Code-gate suffixes:** The last expanded code gates visibly read GCB10 and GCS10 even though their data position is C4 and the code group has four data-code wires. The capture preserves those labels; it does not silently rename them GCB4/GCS4.
- **OCR figure reference:** The Figure 3 explanatory paragraph in the text/OCR refers once to “FIG. 8” while discussing the first/last gates. The inspected drawing is clearly captioned FIG. 3, and this file uses that verified identifier.
- **Intermediate repetition:** First/last gates and abbreviated intervening paths establish repeated channels, but not every intermediate gate label is printed. Additional labels are not invented as direct drawing evidence.
- **Crossings:** Long data/code/strobe routes cross while being rearranged into the output group. Crossings are not treated as a short between wire classes.
- **CODE WIRES grouping:** The grouping includes the strobe member; the prose distinguishes four code lines plus one strobe. It is not interpreted as five independently decoded code bits.
- **Timing:** There is no clock, latch, handshake timing or electrical-driver implementation shown. Inhibit assertion and local launch must not be assumed to have unprinted pulse relationships.
- **Ring context:** Figure 3 shows one station's incoming/outgoing interface; it does not draw the complete ring or device arbitration sequence.
- These are source-capture limits, not claims that the wider repository lacks explanations of those mechanisms.

INTERPRETIVE NOTE

**Figure evidence / DOCUMENTED OBSERVATION:** Incoming sensing remains available before through gating, and local sources combine with the gated through paths. Data has complementary through/launch gating; code and strobe have direct launch inputs to their OR combiners.

**Patent-text evidence / DOCUMENTED OBSERVATION:** IDT, ICT and IST implement selective ring interruption for insertion of station-originated traffic.

**Architectural inference:** The circuit separates observing incoming traffic from forwarding it and supports replacing selected outgoing wire classes. Figure 3 alone does not establish when the higher-level controller asserts each inhibit or launch signal.
