## Direct drawing evidence — PRIMARY EVIDENCE / DOCUMENTED OBSERVATION

### Arrangement and containment

At the left is a tall narrow rectangle labelled CRSEL, with the letters stacked vertically. Four horizontal output paths leave its right side.

Each path passes through a circle containing 2, enters a divided indicator symbol inside a dashed FIR rectangle, then passes through a second circle containing 2 outside FIR. All four data paths run left to right.

The dashed FIR rectangle encloses four indicator symbols, top to bottom:

- MIF20
- MIF21
- MIF22
- MIF23

Each is a narrow upright rectangle divided horizontally into an upper compartment marked 1 and a lower compartment marked 0. The horizontal input/output route meets the upper, 1-marked compartment level. No separate clock or reset wire is drawn beside these symbols.

A common left-side control line labelled TSS branches into the four input gates. A separate right-side control line labelled µPROG SG branches into the four output gates and into one additional upper gate. The rightward outputs are grouped by a tall brace, with endpoint indices 0 above and 23 below. The grouped output arrow is labelled HO, with an O/0-shaped final glyph.

### Common TSS input-gate control

TSS descends as a vertical line between the G8 gates and FIR. At each row a branch runs diagonally left/down into the corresponding gate, ending with an arrowhead:

- TSS → G8/20
- TSS → G8/21
- TSS → G8/22

This is a shared gate-control route, distinct from the four horizontal CRSEL data routes. Its vertical line crosses those data lines; those crossings do not merge the four data paths into one signal.

TSS is not drawn entering the indicator symbols directly, and it is not drawn controlling the G9 output gates.

### Common output-gate control and representative bit-0 path

The vertical line below µPROG SG stands to the right of the G9 gates. It branches diagonally left/down into G9/20, G9/21, G9/22 and G9/23, each with an arrowhead into the gate.

Above G9/20 is an additional circle containing 2:

- A diagonal branch from the same µPROG SG line enters its control side.
- Its output points right beside the label 0.

No G-number or associated indicator symbol is drawn for that upper representative path. There are no individually expanded rows for bits 1–19. The brace spanning this upper path and the lowest row, with indices 0 and 23, conveys the broader grouped output.

The brace is a grouping symbol, not a wire shorting together all output bits. The four labelled G9 outputs and upper representative output remain distinct paths.

### Visible grouping and direction limits

FIR’s boundary encloses only the four MIF symbols shown. CRSEL, all eight labelled gates, the extra upper gate, TSS and the readout-control line lie outside it.

There is no feedback path from readout to the input gates, no link between the four stored indicators, and no direct connection to the separate Figure 6a circuit. No memory, accumulator stack or microprogram control-unit block is drawn here; µPROG SG labels a control input rather than an enclosing controller.

## Patent prose — PRIMARY EVIDENCE, separately attributed

The FIR description says its four most significant bits store the identity of the capability register in use when a capability-related fault is detected. It identifies these as MIF20–23 and associates them with Figure 6b. It also says they are used when the trap indicator is set.

The trap account, paragraph (68), explicitly explains that:

- Microprogram-generated trap-set signal TSS opens gates G8/20, G8/21, G8/22 and G8/23.
- Those gates are the expanded detail of functional gate G8 in Figure 2b.
- The four FIR indicators are set according to the current CRSEL code.
- At that point CRSEL carries the selection/address code of the capability register involved in the instruction’s access.

The prose therefore supplies both TSS’s expansion and the functional meaning of the captured four-bit value. The figure itself prints CRSEL and TSS without spelling out that context.

Paragraph (70) describes the subsequent transfer: microprogram control opens G9 and G10 in the processor diagram and selects the fault-indicator accumulator MFI in ACC STK through RSEL. FIR’s contents, particularly bits 20–23, are then written into that accumulator.

That destination accumulator and G10 are not drawn in Figure 6b. The output grouping is the visible readout detail; its subsequent destination comes from the prose and the joined Figure 2 diagram.

The surrounding processor description identifies circles containing 2 as microprogram-controlled AND gates, typically expanded across parallel signal leads. This supplies their logic interpretation; Figure 6b shows the individual per-bit G8/G9 detail for these four indicators.

## Uncertainties and limits

- **HO/H0:** The grouped output label looks like HO, with a circular final glyph. It is retained literally and also searchable as H0. Its full expansion is not supplied by the cited passages. It is not silently relabelled MHW.
- **µPROG SG:** The label is legible, but SG is not expanded in the cited prose. It controls the output-gate branches as drawn; no independent timing waveform or full microprogram implementation is inferred.
- **Bit-0 representative gate:** Its 2 symbol and data/control arrows are visible, but no gate number or bit-0 storage symbol is printed. Missing intermediate rows are not fabricated.
- **State operation:** Each MIF has 1/0 compartments, but no separate clock, reset input, priority rule or edge-trigger convention is drawn. The prose says TSS causes the four indicators to take the CRSEL states; the drawing does not specify a complete latch implementation.
- **MIF versus MFI:** MIF20–23 are the visible FIR indicator labels. MFI is the separate accumulator destination named in the prose. These related spellings are not collapsed into one object.
- **Code allocation:** The source’s exact numerical mapping from CRSEL selection codes to capability-register names is not printed here.
- **Output width:** The 0/23 brace indicates the wider register-output grouping, while only four stored indicators and a representative top readout gate are expanded. It does not show 24 individual storage cells.
- **Source scope:** The figure details capture and readout of capability-selection identity. It does not draw the trap detector, the change-process sequence, handler entry or later use of the captured value. These limits do not declare those mechanisms unresolved elsewhere in the repository.

INTERPRETIVE NOTE

**Explicit figure evidence / DOCUMENTED OBSERVATION:** Four CRSEL paths are gated by common TSS into MIF20–23 inside FIR, then separately gated out by the common µPROG SG route into the wider output grouping.

**Explicit patent-text evidence / DOCUMENTED OBSERVATION:** These four indicators preserve the selected capability-register identity during trap handling; a subsequent microprogram operation copies FIR to accumulator MFI.

**Architectural inference:** The circuit supports retaining which capability register was involved for subsequent inspection. It stores the selection code shown here, not a complete capability descriptor or an independently drawn snapshot of all process state.
