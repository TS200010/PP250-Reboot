## Direct drawing evidence — PRIMARY EVIDENCE / DOCUMENTED OBSERVATION

### Organisation and graphic conventions

Figure 4 is a register inventory in three vertically stacked groups:

1. SPECIAL PURPOSE CAPABILITY REGISTERS — eight rows.
2. SPECIAL PURPOSE DATA REGISTERS — nine rows.
3. INDICATOR REGISTERS — four rows.

Each row has a short register identifier on the left and a horizontal register-shaped rectangle beside it. Explanatory labels appear to the right. Only seven of the capability rows have connecting arrows, each pointing right into a separate rectangular target box. No data-register or indicator-register row has a connecting arrow to its explanatory text.

There are 21 register rows in total. This is a count of the drawn entries, not a count of all registers implemented by the processor.

### Special purpose capability registers

The heading is exactly SPECIAL PURPOSE CAPABILITY REGISTERS. Top-to-bottom order and arrow destinations are:

| Register label | Rightward arrow and target-box text |
| --- | --- |
| C(D) | → PROCESS DUMPSTACK |
| C(I) | → INTERVAL TIMER WORD |
| C(C1) | → SYSTEM CAPABILITY TABLE 1 |
| C(N) | → NORMAL INTERRUPT BLOCK |
| C(L) | → LOCAL STORE STACK BLOCK |
| C(P) | No arrow and no right-hand target box or explanatory label. |
| C(C2) | → SYSTEM CAPABILITY TABLE 2 |
| C(S) | → SPECIAL START UP BLOCK |

The numerals 1 and 2 in C(C1), C(C2) and the table names are part of those identifiers. They are not separate reference-numeral callouts. C(I) contains the letter I.

All eight capability-register symbols have the same visible subdivision:

- An outer horizontal rectangle.
- A horizontal line dividing it into an upper strip and a lower strip.
- A vertical divider near the left of the lower strip, making a short lower-left compartment and a longer lower-right compartment.
- No labels, bit numbers, values or widths inside any compartment.

The seven arrows leave the right edge of the register symbols at the level of their upper strips and enter the left edges of their respective target boxes. Every arrow points from register toward target; none points back. C(P) retains the same three-compartment symbol even though its target area is blank.

The target boxes are independent horizontal rectangles, not a single shared store block. There are no links between the target boxes, no links between capability rows, and no branches or return arrows. The two system-capability-table rows are separated in the printed order: C(C1) is third, while C(C2) is seventh, below C(P). This ordering is preserved rather than rearranged into numerical order.

### Annotations, labels and direction limits

The only arrowheads in the figure are the seven rightward capability-to-target arrows listed above. They convey the displayed register/target relationship. They are not explicitly labelled as data transfer, control flow, read access, write access, loading, or change-process operations.

## Patent prose — PRIMARY EVIDENCE, separately attributed

The brief description says Figure 4 shows special-purpose data and capability registers provided in the CPU. The drawing additionally has its explicit INDICATOR REGISTERS group.

The full patent transcription supplies functional explanations not printed within Figure 4. Selected explanations directly relevant to the displayed entries are:

### Capability-register targets

- **C(D):** The prose says it contains base/limit addresses and an access code for the active process’s dump stack and is changed by CHANGE PROCESS. Paragraph (28) calls this the “Processor Dump-Stack”; the drawing’s target reads PROCESS DUMPSTACK. The drawing wording is preserved without silently reconciling the terminology.
- **C(I):** Defines a store block whose first word contains the interval timer value. The prose describes decrementing it every 100 microseconds and generating a normal interrupt at zero. The drawing itself shows only INTERVAL TIMER WORD.
- **C(C1) and C(C2):** Define blocks containing the first and second parts of the system capability table.
- **C(N):** Defines a store block whose first word contains a capability pointer permitting entry to the normal-interrupt process.
- **C(L):** Defines a store block for the current process’s local store stack; the prose says it changes with CHANGE PROCESS.
- **C(P):** The prose identifies its use by the Programmer Interface when accessing store. No such label or arrow is present beside C(P) in the drawing.
- **C(S):** The prose describes a four-word store block used in fault-interrupt handling, with the most significant 12 base-word bits incremented during the fault sequence and the remainder preset following power-up. The drawing’s target name is SPECIAL START UP BLOCK; it does not draw the four words or the altered base bits.

The prose describes capability descriptors in terms of base, limit and access information. Those concepts help explain the register symbols but are not labels printed in the three compartments of Figure 4. This capture does not assign numerical widths or particular fields to those compartments from shape alone.

### Data-register subdivisions and sizes

The prose explicitly states:

- PDSPR holds an absolute-address pointer to the current top of the process dump stack, pointing to the first word available for dumping.
- LNR has a most significant 8-bit current link-level number and a least significant 16-bit relative-address pointer.
- LCCR has a most significant 8-bit local-capability count and a least significant 16-bit local-store-clear count.
- The special-purpose data registers are 24 bits long except IR.
- IR contains a single bit, bit 6, set when a Program Trap is accepted.
- FIDR holds the fault-indicator-register state following the first fault interrupt.
- D(A) and D(B) are accessible through internal-mode data instructions and are described as unused by processor functions.
- IAR contains the absolute address of the current instruction within the program block specified by C(7).

These are prose-supplied properties, not visible bit allocations in Figure 4. In particular, the LNR and LCCR separators show two parts but have no printed 8/16 labels, and the uniform IR outline does not depict its single-bit semantics.

### Indicator group

The prose identifies PIR, FIR, TR and HR as primary, fault, test and historical indicator registers, accessible in internal mode. It describes PIR’s process-state role, FIR’s fault conditions, TR’s testing facilities and HR as a group of sixteen 26-bit registers addressed one at a time through a 4-bit counter, forming a circular queue.

Figure 4 shows only one undivided HR outline; it does not draw the sixteen entries, the counter, queue links or any indicator bit allocation. The prose’s functional details must therefore remain distinct from the drawn inventory.

## Uncertainties and source limits

- All 21 register identifiers, the three headings and the seven target labels are reasonably legible. No missing C(P) target has been reconstructed from prose and inserted as drawing evidence.
- The register compartments are unlabelled. Their exact field mapping, bit ordering and widths cannot be read from this figure alone.
- The lengths of the drawn registers are schematic. They do not establish equal bit widths across the capability, data and indicator groups.
- Capability arrows point right, but their operational meaning is not labelled. They must not be read as a complete datapath or proof that an operation transfers data in only that direction.
- PROCESS DUMPSTACK in the drawing and “Processor Dump-Stack” in the C(D) prose are retained as separate source wordings. No additional stack or architectural distinction is inferred from that wording difference.
- The figure-specific plain-text transcription reproduces the names and associations but omits the register-box subdivisions. Those subdivisions here come from inspection of the PDF.
- Figure 4 contains no access-permission table, internal-mode address allocation, register-selection mechanism or loading sequence. Those belong to other figures and the prose and have not been imported into the factual drawing capture.
- These are limits of this figure and its accompanying prose, not declarations that corresponding architectural details remain unresolved elsewhere in the repository or that the depicted later register inventory applies to every earlier System 250 configuration.

INTERPRETIVE NOTE

**Explicit figure evidence / DOCUMENTED OBSERVATION:** The drawing distinguishes capability registers associated with named blocks or a timer word, special-purpose data registers, and indicator registers. Capability symbols have three unlabelled compartments; LNR and LCCR each have two. C(P) is present without a drawn target.

**Explicit patent-text evidence / DOCUMENTED OBSERVATION:** The prose supplies the capability targets’ roles, the LNR/LCCR 8/16-bit divisions, and internal-mode access to these register classes.

**Architectural inference:** Figure 4 serves as an inventory and association diagram rather than a complete wiring or access-control specification. Its grouping supports distinguishing capability-held block descriptions from data and indicator state, but exact addressing, permissions, update rules and startup behaviour require the separate prose and other figures.
