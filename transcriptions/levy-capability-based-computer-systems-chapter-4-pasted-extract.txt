4.1 Introduction
The second attempt to build a capability-based hardware addressing system was made by the Plessey Corporation in the United Kingdom. Plessey’s System 250 [England 72a, England 74], examined in this chapter, was not only the first operational capability hardware system but also the first capability system sold commercially.
Initially the Plessey 250 was not designed as a capability system. Maurice Wilkes of the University of Cambridge had learned about capabilities during several visits to the University of Chicago and had included a capability description in his book on timesharing systems [Wilkes 68]. Wilkes sent a draft of his book to Plessey’s Jack Cotton who incorporated capability concepts into the System 250. Because of the strong resemblance between the System 250 and the Chicago effort, Bob Fabry (who had worked on the Chicago Magic Number Machine) later acted as a consultant for Plessey.
Unlike the systems examined thus far, the Plessey 250 was not intended to be a general-purpose timeshared computer. Instead, it was designed as a highly reliable, real-time controller for a new generation of computerized telephone switching systems [Cosserat 72, Halton 72]. The reliability goal was very stringent: mean time between failures of 50 years [Hamer-Hodges 72]. Meeting this goal required that the system be easily configured, tested, and modified while operating in the field. Service improvements or performance upgrades would have to be performed while the system was operational. Such needs led to a multiprocessing design that allowed connection of many processors and memories, as well as traditional and specialized I/O devices.
Although capabilities were used primarily for memory addressing and protection in the Plessey 250, the designers viewed the capability mechanism as a means of restricting the effects of faulty hardware and software components. Fault isolation was a major concern in a multiprocessing environment where several processors had access to a shared memory. One faulty processor could potentially damage another processor’s computation. Capability addressing facilitated sharing among processors, while also restricting each processor’s domain to the segments for which it possessed capabilities. The Plessey 250’s designers also found that capabilities were useful in structuring the operating system [England 72b, Cosserat 74]. Layering and data abstraction were important aspects of the Plessey operating system design.

4.2 System Overview
The multiprocessing architecture of the Plessey 250 allows connection of up to eight processors with up to eight storage modules through separate per-processor data paths. Each storage module consists of up to 64K 24-bit words. Multiprocessing is symmetric, and any processor can perform any function if another processing component fails. Peripherals are connected and controlled through interfaces that allow the addressing of devices as memory. That is, device registers can be read and written by standard LOAD and STORE instructions, and no special I/O instructions are needed.
The Plessey 250’s hardware and operating system support a segmented memory space. A segment can contain capabilities or data, but not both. The system has a general register architecture with eight 24-bit data registers (D0-D7) and eight 48-bit capability registers (C0-C7). To access data in a memory segment, a program must load one of the capability registers with a capability for that segment. Programs can freely copy capabilities between capability segments and capability registers using standard hardware instructions.

4.3 Capability Addressing
A Plessey 250 capability permits its possessor to access an object in the system, where an object is a logical or physical resource. The most basic object is a memory segment, and hardware instructions can operate directly on segments through segment capabilities. Capabilities can be stored in capability segments or capability registers, as noted above. For each program, one of its capability registers (C6 by convention) points to a Central Capability Block for the program. The Central Capability Block is a capability segment that is the root of a network of program-accessible segments. The closure of this network completely defines the program’s execution domain.
A capability in the Plessey 250 has two formats, depending on whether it is stored in a capability segment or a capability register. When stored in a 48-bit capability register, a capability contains a base address, a limit, and an access rights field. The six unary-encoded access rights are execute, write data, read data, enter capability, write capability, read capability.
This 48-bit capability format, which includes a memory address and limit, is used only when capabilities are loaded into capability registers. When stored in a capability segment, a capability is 24 bits and contains only the access rights field and an index into a central system data structure, the System Capability Table (SCT). Each processor has an internal register that contains the address of the SCT. The SCT holds the base and limit information for all memory segments. Physical addressing information is thereby centralized and relocation simplified. There is one SCT entry for each object in the system. Because access rights for an object are stored in the capabilities, different processes can possess capabilities permitting different access rights to the same segment.
A program executes a LOAD CAPABILITY instruction to transfer a capability from a capability segment to a capability register. The hardware examines the SCT index in the specified capability in memory. This index selects the SCT entry for the segment, which is three words in size and contains a 24-bit checksum and special flag bits in addition to base and length fields. The 48-bit capability register is constructed from the rights field in the capability and the base and limit information found in the selected SCT entry. The capability segment from which the capability is loaded must itself be addressed by a capability register.
When a program loads a capability register, the SCT index from the loaded capability is saved in a process-local data structure called the Process Dump Stack. The dump stack is a two-part process data structure containing fixed space for copies of data and capability registers, and a stack used to save information on procedure invocations. When a program executes a STORE CAPABILITY instruction to move a capability from a register to a capability segment, the saved SCT index is used, along with the rights field in the register, to construct the capability in memory. The Process Dump Stack is thus used to hold the SCT index for each capability stored in the eight capability registers.
Because the SCT is shared by all processors, relocation of a segment or modification of an SCT entry must be synchronized. The Plessey 250 has a facility to trap programs accessing a particular entry so a processor updating an SCT entry can prohibit other processors from using it until modification is complete.

4.4 Capability Register Usage
C0-C4 can be freely used by the program to address memory segments to which the program has access. C5 points to a data structure used to store dynamically allocated elements associated with current process execution. C6 contains a pointer to the process’s Central Capability Block. C7 contains a capability for the currently executing code segment.
In addition to the eight program-accessible capability registers, each processor has five special-purpose capability registers addressing the Process Dump Stack, System Capability Table, Start-up Block, System Interrupt Word, and Normal Interrupt Block.

4.5 Inform and Outform Capabilities
The Plessey 250 operating system provides a virtual segment interface. Secondary storage is transparent to the program. Each segment has an associated disk address assigned when the segment is created and used as its unique identifier. When a program creates a segment, the operating system assigns secondary storage, allocates an SCT entry, and returns a capability. Primary memory can then be allocated when the segment is first referenced.
SCT entries can be reallocated. Capabilities in primary memory are inform or active capabilities containing an SCT index. Capabilities in secondary memory are outform or passive capabilities containing the object’s unique disk address. When a capability segment moves between primary and secondary memory, the operating system changes the form of all capabilities in the segment. A garbage collector can deallocate an SCT entry when no active capabilities exist or delete an object when no capabilities exist at all.

4.6 Instructions and Addressing
A Plessey 250 instruction occupies a 24-bit word and has store and direct formats. Store mode instructions specify a capability register, a 9-bit offset and optional index register modifier. The primary memory address is calculated from the capability base plus offset and index; the address is checked against the limit and the requested access against the rights field. Direct mode instructions do not require memory access and are used for literals or register-to-register operations.

4.7 Protected Procedure Calls
The Plessey 250 has no privileged mode of operation. The operating system relies on the protected procedure mechanism for protection. A protected subsystem is built by creating a Central Capability Block containing capabilities for its code, data and capability segments. Execute capabilities identify procedures implementing services. The subsystem passes an enter capability for its Central Capability Block to users, who can call procedures defined by execute capabilities but cannot directly access capabilities in the block.
CALL specifies an enter capability for a Central Capability Block and an offset locating an execute capability. CALL saves the instruction pointer and C6 and C7 on the Process Dump Stack. C6 is loaded with the called Central Capability Block and C7 with the procedure’s instruction segment. RETURN restores C6, C7 and the program counter.

4.8 Operating System Resource Management
The Plessey 250 operating system is constructed as protected subsystems managing resources. Supported resources include storage segment, process, user, job, text file, symbol directory, data stream and synchronizing flag. Logical resource capabilities are enter capabilities allowing users to request services for the resource.
Users gain access to operating system services through a Central Facilities Block containing enter capabilities for system resource allocation routines. A creation routine returns an entry capability for the resource. The actual representation of a resource is defined by the Central Capability Block pointed to by that enter capability. It contains execute capabilities for procedures manipulating the resource and capabilities for segments holding its state. A separate Central Capability Block exists for each resource instance, while resources of the same type share code segments.

4.9 Input and Output
I/O device registers exist in the physical address space and require a capability for that memory space. Device driver processes possess capabilities for device registers and can execute on any processor. Standard interrupts are abandoned in favour of polling shared memory; approximately every 100 microseconds processors examine I/O status words addressed through special capability registers.

4.10 Discussion
Levy identifies System 250 as the first functioning capability-addressing computer and the first commercially produced capability-based computer, designed for critical real-time reliability and multiprocessing. Stored capabilities contain a table index rather than physical addresses; disk capabilities use a different form; and segment identity permits conversion between inform and outform forms.
Primary memory addresses exist only in the SCT and capability registers of executing processes. When a process is pre-empted its expanded capability registers are not saved; the Process Dump Stack retains SCT index and access rights from which registers can be regenerated.
Capabilities simplify multiprocessing because processes can address their segments from any processor through the shared SCT. They also confine software errors to the domains for which processes possess authority.
System 250 presents a uniform resource model: resources are addressed by capabilities; hardware directly operates on segment resources while software implements operations on logical resources. Each resource is represented by a Central Capability Block and addressed by an entry capability. The block defines state segments and manipulation procedures; procedures are shared among resource instances.
Levy notes a weakness in protected procedure calls: C0-C4 survive the domain change. Capabilities left there by the caller remain accessible to the called procedure, and capabilities left by the called procedure remain available to the caller after return. Clearing these registers can prevent leakage but imposes a burden on software.
